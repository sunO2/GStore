# 构建、测试与发布

> 开发 Wiki 第八篇 · 环境、构建命令、测试与 CI

## 1. 环境要求

| 组件 | 版本 |
| --- | --- |
| Flutter | >= 3.44（当前 3.44.x 已验证） |
| Dart | >= 3.5.3 |
| Android Gradle Plugin | 8.11.x |
| Gradle | 8.14 |
| Kotlin | 2.2.x |
| Rust | stable（flutter_rust_bridge 2.11.1） |
| Android NDK | 26.x（Rust 交叉编译用） |

## 2. 依赖安装

```bash
flutter pub get
```

> 注意：`installed_apps` 来自 GitHub 依赖（shatanikmahanty/installed_apps，master 分支），首次拉取需网络。

## 3. 常规构建

```bash
# 分析
dart analyze lib/

# 单元测试
flutter test

# 构建 APK（仅 arm64）
flutter build apk --release --target-platform android-arm64
```

## 4. Rust 库构建（首次 / 变更后必需）

项目包含 Rust 侧 F-Droid 解析库，Android 构建前需先交叉编译：

```bash
# 方式一：一键脚本（推荐）
./build_android_rust.sh

# 方式二：独立构建
./build_android_standalone.sh

# 简化构建
./build_android_simple.sh
```

- 脚本使用 NDK 交叉编译 `rust/fdroid_repo`，输出到 `android/app/src/main/jniLibs`。
- Rust 变更后需重新生成 FFI 绑定：
  ```bash
  cd rust/fdroid_repo
  flutter_rust_bridge_codegen generate
  ```
- 详见 `rust/BUILD_ANDROID.md` 与 `rust/ANDROID_BUILD.md`。

## 5. 生成代码（build_runner）

Floor 表、json_serializable、retrofit 使用 codegen：

```bash
dart run build_runner build --delete-conflicting-outputs
```

涉及：

- `lib/db/apps/AppInfoDatabase.g.dart`
- `lib/core/model/BackupData.g.dart`
- `lib/http/github/*.g.dart`
- `lib/core/config/config_backup.g.dart`
- 各 Floor 数据库 `.g.dart`

> 修改了带 `@JsonSerializable` / `@Entity` / `@RestApi` 注解的类后必须重新生成。
> 测试中依赖生成的序列化行为（如 BackupData 嵌套对象在 jsonEncode 时才展开）。

## 7. 版本管理

- 版本号在 `pubspec.yaml`（当前 `1.0.24+1`）。
- 用户未要求时不主动改版本。
- 发布 Release 时同步更新版本号并打 tag。

## 8. 开发规范（AGENTS.md 摘要）

- **主题**：Material 3 + 主题令牌，禁止硬编码颜色/字号（见 `theme-usage-guide.md`）。
- **确认框/提示框**：一律 `AppDialogs.showDialog`（危险操作加 `isDangerous: true`）。
- **loading**：`AppLoading` / `AppLoadingSize`。
- **COLR 图标**：`AliIcon` 必须用 `ColoredAliIcon` 染色。
- **日志**：用 `debugPrint`（main.dart 已重定向到日志查看器）。
- **验证**：改完跑 `dart analyze lib/`、`flutter test`、`flutter build apk --release --target-platform android-arm64`。
- **git push** 用 SSH：`git@github.com:sunO2/GStore.git`。
- **提交**：按修改点分批提交，先审阅 `git status` / `git diff`，不提交密钥。

## 9. 工作流模块（补充）

`lib/core/workflow/` 提供可视化工作流设计器与执行引擎：

- `WorkflowModel`：工作流（步骤、变量、拓扑排序）。
- `WorkflowEngine`：执行入口（含重试）。
- `StepExecutorRegistry` + 各 Executor：HTTP 请求、数据提取、转换、过滤、排序、去重、延迟等步骤。
- 设计器页面：`lib/page/workflow/`（路由 `/GStore/workflowDesigner`）。

## 10. 日志系统

- `lib/core/logger/LogManager.dart`：分类日志（appLog.debug/info/error），main.dart 将 debugPrint 重定向。
- 页面 `lib/page/log_viewer/`：日志查看器（路由 `/GStore/logViewer`）。
- 已过滤 flutter_gen_ai_chat_ui 库的内部调试噪音（见 main.dart `_chatUiNoisePatterns`）。
