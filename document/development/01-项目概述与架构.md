# 项目概述与总体架构

> 开发 Wiki 第一篇 · 面向新加入的开发者

## 1. 项目简介

GStore 是一个**基于开源数据的跨渠道软件商店**，为 Android 用户提供安全、可审计的应用发现、下载、更新与备份体验。所有应用数据均托管在开源仓库 [GStore-Repositorys](https://github.com/sunO2/GStore-Repositorys)，任何人都可以查看、审计与贡献。

核心设计原则：

- **渠道抽象**：通过统一的 `IChannel` 接口聚合 GitHub、F-Droid、vivo、HTTP API、本地数据库等多种软件来源。
- **数据开放**：应用数据完全开源，支持一键更新数据库（带版本检测与增量提示）。
- **本地优先**：内置本地数据库渠道，无网络时仍可浏览已收录应用。
- **安全可控**：GitHub 代理加速、Shizuku 静默安装、URL 校验、日志查看器。

## 2. 技术栈

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| UI 框架 | Flutter 3.44+ / Dart 3.5+ | Material 3 + 自定义主题令牌 |
| 状态管理 | GetX | `GetxController` / `Rx` / 路由 |
| 本地数据库 | Floor (SQLite) + sqflite | 应用表、下载状态表、F-Droid 索引表 |
| 网络 | Dio + retrofit + rhttp | 统一拦截器、GitHub 代理 |
| 多段下载 | 自研 `segment/` 模块 | 断点续传、Range 请求、段合并 |
| 静默安装 | Shizuku + app_installer | 免确认安装，未授权回退系统安装器 |
| Agent 助手 | Google Genkit | gemini / OpenAI 兼容模型，工具调用 |
| 聊天 UI | flutter_gen_ai_chat_ui | 流式渲染、Markdown、时间轴 |
| F-Droid 解析 | 自研 Rust (flutter_rust_bridge) | index-v2 解析、APK 信息解析 |
| 备份 | archive 包 | tar.gz / JSON 导出导入 |
| WebDAV | 自研 `webdav_client.dart` | PROPFIND/PUT/GET/MKCOL |
| 配置存储 | SharedPreferences + secure_storage | 主题、下载、WebDAV 凭据 |

## 3.1 模块化架构（ModuleManager）

GStore 采用**模块化 + 热插拔**架构（参考 Java 动态代理思想）：

```
调用方（页面/Agent）
   │ 不直接依赖具体类，只依赖接口
   ▼
ModuleManager（lib/core/module/）
   ├── get<T>() / require<T>()   # 编译期绑定，0 损耗主路径
   ├── registerModule()          # 模块登记（上线）
   ├── activate()                # 登记 + 初始化（热插拔上线一步完成）
   ├── initializeAll()           # 依赖拓扑排序 + 分层并行初始化
   ├── initializeModule()        # 单模块上线（自动递归初始化依赖）
   ├── unregisterModule()        # 模块下线（全部联动注销）
   └── onChange                  # 上下线事件（热插拔感知）
        │
        ├── DynamicProxy         # 可选动态代理（延迟绑定/AOP 拦截）
        └── AppModule            # 生命周期钩子（onInit 初始化 / onRegister 绑定 / onUnregister 下线）
              ├── dependencies / serviceDependencies   # 依赖声明（类似 Linux 包管理器）
              └── 联动：ConfigModule（配置上下线）+ AgentToolModule（工具上下线）+ 服务接口绑定
```

- **依赖注入式初始化**：模块声明 `dependencies`（模块名）/`serviceDependencies`（服务类型），
  `initializeAll` 自动补注册缺失依赖 → 环检测 → 拓扑分层 → 同层并行（Future.wait）初始化。
- **性能**：主路径 `ModuleManager.get<T>()` 为 O(1) Map 查找，调用方缓存引用后方法调用是编译期绑定（真正 0 损耗）；`DynamicProxy` 动态代理仅用于需要运行期拦截/延迟绑定的场景。
- **配置上下线**：模块上线时 `ConfigService.registerModule(ConfigModule)` 注册配置，下线时注销——Agent 的 `configManager` 工具自动反映可用配置。
- **Agent 工具上下线**：`AgentToolModule` 上线/下线即增删模型可调用的工具清单（defineTool + AiAction 动态构建）。

详见《核心模块-模块化框架》。

## 5. 启动流程（main.dart）

1. 重定向 `debugPrint` → 日志管理器（过滤 ai_chat_ui 噪音）。
2. 注册 GetX 依赖：`LogManager`、`DbManager`、`UserManager`、`DatabaseEventBus`、`AppAggregatorManager`、`FdroidRepoManager`、`BadgeService`、`ThemeController` 等。
3. 初始化各渠道（`ChannelIntegration.initialize`）。
4. 进入 `HomePage`。

## 6. 全局入口 core.dart

`lib/core/core.dart` 是核心层的统一出口（大量 `export`），并提供：

- `getProxy() / updateProxy()`：GitHub 代理前缀管理（默认 `https://gh-proxy.org/`，空串表示不使用）。
- `getConfig()`：获取 `AppInfoConfig`（版本 + 代理）。
- `updateDataBaseVersion()`：数据库版本更新。

> 注意：业务代码里引用 `AppConfig`、`ChannelManager`、`BackupService` 等时，通常直接 `import 'package:gstore/core/core.dart'`。

## 7. 数据流示例：搜索并下载一个应用

```
用户输入关键词
  → SearchPage (search) → ChannelManager.searchApps
  → 遍历 ChannelType.values 逐个渠道调用 IChannel.searchApps
  → 聚合结果 → 点击进入详情页 DetailPage
  → 点击下载 → DownloadService.download (GitHub 渠道自动匹配 CPU 架构)
  → 多段下载 (SegmentPlanner/Downloader/Merger) 或单段下载
  → 下载完成 → InstallManager.installApk (Shizuku 静默 / 系统安装器)
```
