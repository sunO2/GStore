# 核心模块：配置中心与主题系统

> 开发 Wiki 第六篇 · ConfigService、模块化注册、设计系统与主题

> ⚠️ **现状校正（Rust config core 已落地）**：用户配置的**唯一权威**是 Rust core
> （`rust/gstore_core/src/config/`，SQLite `config_entry` / `config_change_log` /
> `config_meta`，迁移 `V6__config.sql`）。Dart `ConfigService` 是 Rust `ConfigApi`
> 的薄门面；`ConfigStore` / `ConfigManager` 仅为兼容/测试 seam，不再拥有持久化权威。
> 旧的 `on_event("config.changed")` 全模块广播已删除（Todo 36）；Rust 模块改用
> ABI v5 过滤订阅。架构、键表、迁移、回滚与备份 v2 契约见
> [`docs/config-architecture.md`](../../docs/config-architecture.md)。
> 下文 §1 保留部分历史描述，**以本校正与新文档为准**。

## 1. 配置中心（config/）

### 权威链路

```
写入方（UI / Agent / 模块 / 迁移 / 恢复）
  → Dart ConfigService（元数据镜像 + 默认真脱敏）
  → Rust ConfigApi（get/set/list/watch/import/export/snapshot）
  → ConfigStore（单事务提交：config_entry + config_change_log + config_meta.revision）
  → ConfigBus（按 (module, key) 过滤、按条目可见性逐条裁决）
  → Dart watch 流 / ABI v5 模块订阅
```

### ConfigService（统一门面，推荐入口）

`lib/core/config/config_service.dart`：

| 能力 | 说明 |
| --- | --- |
| 元数据水合 | `ensureReady()` 从 Rust 注册表 `ConfigApi.list()` 同步到本地 `ConfigEntry` 映射 |
| 读写委托 | 全部走 Rust；`get`/`getT` 默认脱敏，`getRaw` 是可信原始读 |
| 敏感策略 | 镜像**绝不缓存秘密明文**；敏感项读取显示 `***` |
| 订阅 | `watch`/`watchMany`/`watchModule` 把过滤器下推给 Rust `ConfigApi.watch` |
| 兼容面 | 保留 `ConfigEntry`/`hasModule`/`markSensitive`/`sensitiveKeys`/`initialize({storages})` 等 seam |

```dart
await ConfigService.instance.set(ConfigKeys.themeMode, 2, source: ConfigChangeSource.agent);
ConfigService.instance.watch(ConfigKeys.themeMode).listen((e) { ... });
final snaps = await ConfigService.instance.snapshots();
```

**核心架构**：写入方只写配置；Rust store 提交后由过滤总线通知 Dart 与已订阅模块。

### ConfigStore（兼容/测试 seam）

`lib/core/config/config_store.dart`：经 `ConfigBackend` seam 路由到 Rust 适配器或
内存 fake；保留 `markSensitive`/`isSensitive`/`sensitiveKeys`/`resetForTest`/
`initialize({storages})`。它**不再是**权威存储，也不再自发产生 `config.changed` 广播。

### ConfigStorage（测试用存储抽象）

`config_storage.dart`：仅供旧测试与内存 fake 使用；生产持久化在 Rust。

### ConfigManager（旧入口，兼容保留）

`config_manager.dart`：仅作旧调用点兼容；新代码使用 `ConfigService` / Rust `ConfigApi`。

### 内置注册表

- **权威注册表**：`rust/gstore_core/src/config/schema.rs`（12 模块 / 53 键；
  `module.key` 规范形式，含类型、默认值、可见性、敏感标记、范围/枚举）。
- `lib/core/config/config_registry.dart` 的 `ConfigKeys` 保留为 Dart 侧 wire key 常量与
  旧备份别名来源，不再定义新键。
- 新增配置必须先登记到 Rust 注册表，再在 Dart 侧使用。

### 配置备份

- 导出：`BackupService` 经 `ConfigService.exportRaw()` → `ConfigApi.export()` 生成
  grouped `configs` + legacy 别名 + top-level `proxy_url`/`webdav_config` 镜像，
  写 `config_format: 2`（`ConfigBackupData.version` 仍为 1）；`includeAppConfig=false`
  时整体省略配置载荷，绝不用 `***` 掩码代替。
- 恢复：`ConfigRestoreAdapter` 同时读 `apps.json.appConfig` 与 `app_config.json`，
  grouped 优先于 legacy 别名/top-level 镜像，逐 key 报告失败且不含值。
- 迁移：`ConfigMigrationTool` 一次性把 legacy 键导入 Rust，回读校验后写
  `config.migrated.v1` 标记；旧键永不删除以保留回滚能力。

## 2. 设计系统（core/design/）

> 遵循 Material 3 + 主题令牌，**禁止硬编码颜色/字号**。

| 文件 | 内容 |
| --- | --- |
| `design_tokens.dart` | 设计令牌统一出口 |
| `app_colors.dart` | 颜色（用 `Theme.of(context).colorScheme`，不直接用 Colors.xxx） |
| `app_typography.dart` | 字号/字重（`AppTypography.sizeLG` 等） |
| `app_spacing.dart` | 间距（`AppSpacing.allLG` / `sm` 等） |
| `app_radius.dart` | 圆角（`AppRadius.allMD`） |
| `app_shadows.dart` | 阴影 |
| `app_animations.dart` | 动画 |
| `app_dialogs.dart` | 统一对话框入口（`AppDialogs.showDialog` / `showSuccess` / `showError`） |
| `app_components.dart` | 通用组件（`AppLoading` / `AppLoadingSize` / 按钮等） |

### 核心规则（务必遵守）

1. 颜色/文字一律 `Theme.of(context).colorScheme` / `.textTheme`。
2. 确认框/提示框一律 `AppDialogs.showDialog`（危险操作 `isDangerous: true`）。
3. loading 用 `AppLoading` / `AppLoadingSize`。
4. COLR 彩色字体图标 `AliIcon` 必须用 `ColoredAliIcon` 染色（夜间模式可见）。
5. Snackbar 用 `AppDialogs.showSuccess` / `showError`。

## 3. 主题系统（theme/）

### 文件

| 文件 | 说明 |
| --- | --- |
| `theme_controller.dart` | `ThemeController`：主题模式（system/light/dark）+ 主题配置流 |
| `theme_data_builder.dart` | 从配置构建 `ThemeData`（Material 3） |
| `theme_utils.dart` | 工具函数 |
| `app_theme_config.dart` | `AppThemeMode` 枚举与 `AppThemeConfig` |

### 能力

- `AppThemeMode.system/light/dark` 切换，支持循环切换（`toggle`）。
- 自定义主色（首页"我的"提供 6 色快捷选择）。
- Android 12+ 动态取色（dynamic_color 包）由 `theme_data_builder` 集成。

### 持久化与订阅者模式

- 写入统一走 ConfigService（`setThemeMode` → `ConfigService.set(theme.mode)`），
  ThemeController 订阅 Rust 过滤后的配置流，配置变化后主动更新 Rx → UI 自动刷新。
  旧 `config.changed` 下行广播已删除；Rust 侧若需感知主题变更，使用 ABI v5 过滤订阅。
- `theme.mode` 是 `PublicRead` 键（0=system / 1=light / 2=dark），其他模块可只读订阅。
- 启动时 `ThemeController` 加载恢复。
