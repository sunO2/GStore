# 核心模块：渠道系统

> 开发 Wiki 第二篇 · 渠道抽象与聚合

## 1. 概述

渠道（Channel）是 GStore 的数据来源抽象。所有渠道实现统一的 `IChannel` 接口，上层通过 `ChannelManager` 访问，屏蔽了各来源的差异。

```
IChannel（接口）
  ├── LocalDbChannel   本地数据库（离线可用）
  ├── GitHubChannel    GitHub API / 仓库 Release
  ├── HttpChannel      HTTP API 自定义来源
  ├── VivoChannel      vivo 应用市场
  └── FdroidChannel    F-Droid 仓库（本地索引）
```

## 2. 接口定义（IChannel.dart）

```dart
abstract interface class IChannel {
  ChannelType get channelType;
  Future<bool> checkAvailable();                       // 渠道可用性探测
  Future<ChannelResult<List<AppInfo>>> getAllApps();   // 全量应用
  Future<ChannelResult<AppInfo?>> getAppInfo(...);     // 单个应用
  Future<ChannelResult<IDetailInfo>> getAppDetail(...);// 应用详情
  Future<ChannelResult<AppUpdateCheckResult>> checkAppUpdate(String appId);
  Future<ChannelResult<void>> addApp(AppInfo app);     // 添加应用到渠道库
  Future<ChannelResult<void>> removeApp(String appId);
  Future<ChannelResult<List<AppInfo>>> searchApps(...);// 搜索
  Future<ChannelResult<List<AppInfo>>> searchByCategory(...);
  Future<ChannelResult<bool>> checkUpdate();           // 渠道数据源更新检测
  Future<ChannelResult<bool>> doUpdate();              // 执行数据源更新
  Future<ChannelResult<db.AppInfoConfig?>> getConfig(...);
}
```

`ChannelResult<T>` 统一承载 `success / data / error / message`。

## 3. 渠道类型（ChannelType）

```dart
enum ChannelType {
  localDb('local_db', '本地数据库', 1),
  github('github', 'GitHub API', 2),
  http('http', 'HTTP API', 3),
  vivo('vivo', 'vivo 应用市场', 4),
  fdroid('fdroid', 'F-Droid', 5),
  custom('custom', '自定义', 99),
}
```

- `code`：渠道代码（也是数据库中的 channel 字段）。
- `priority`：渠道优先级（数值越小越优先）。
- `fromCode(String)`：按 code 反查枚举。

## 4. ChannelManager

`lib/core/channel/ChannelManager.dart`，单例，统一入口：

| 方法 | 说明 |
| --- | --- |
| `getAllApps` | 全量应用（可带 fallback 到本地） |
| `getAppInfo` / `getAppDetail` | 应用信息/详情 |
| `searchApps(keyword, {from})` | 搜索（可指定渠道） |
| `searchByCategory` | 分类搜索 |
| `checkUpdate` / `doUpdate` | 数据源更新 |
| `checkAllUpdates` | 所有渠道批量更新检测 |
| `checkAvailableChannels` | 探测各渠道可用性（逐个超时回退） |
| `clearCache` / `getTotalCacheSize` | 缓存管理 |
| `initializeAll` / `disposeAll` | 生命周期 |

### 搜索流程

`searchApps` 遍历所有渠道并聚合结果；支持 `from` 参数限定单渠道。Agent 搜索时也复用此入口（`_searchApp`）。

## 5. 各渠道实现要点

### LocalDbChannel

- 数据来自本地 `AppInfo` 表（由数据仓库更新导入）。
- 离线可用；`getConfig` 返回持久化的数据库版本与代理配置。

### GitHubChannel

- 通过 GitHub API 搜索仓库 / 读取 Release 资产。
- APK 下载时**自动匹配设备 CPU 架构**（见 `platform_arch.dart` 的 `assetMatchesDevice`）。
- 支持代理前缀（`getProxy()`），国内访问加速。
- appId 使用 `owner/repo` 格式（如 `termux/termux-app`）。

### HttpChannel

- 自定义 HTTP API 来源，按配置的接口返回统一 JSON 格式。

### VivoChannel

- vivo 应用市场渠道；应用标识为 `vivoId`。
- Agent 场景下若缺少 vivoId，会通过搜索自动解析（`_resolveVivoId`）。

### FdroidChannel

- 基于本地 F-Droid 索引数据库查询（由 `FdroidRepoManager` + Rust 解析器维护）。

## 6. 聚合数据库（AppAggregatorManager）

`lib/core/aggregate/AppAggregatorManager.dart`：

- 维护 "我的应用" 聚合列表（`AppAddedDatabase`，表 `AddedAppInfo`）。
- API：`addApp` / `addApps` / `removeApp` / `toggleApp` / `getAllAddedApps` / `getAppsByChannel` / `isAppAdded` / `getTotalCount` / `getCountByChannel` / `clearChannel` / `clearAll`。
- 首页 "我的应用"、渠道应用管理、备份导出均依赖此模块。

## 7. 扩展一个新渠道

1. 在 `ChannelType` 枚举中增加渠道（code / 描述 / 优先级）。
2. 实现 `IChannel`（参考 `impl/GitHubChannel.dart`）。
3. 在 `ChannelManager` 的渠道注册表中注册。
4. （可选）在 `AppAggregatorManager` / 备份导出中补充渠道处理。
5. 运行 `dart analyze lib/` 与 `flutter test` 验证。
