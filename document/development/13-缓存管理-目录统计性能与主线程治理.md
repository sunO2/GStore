# 缓存管理页卡顿：根因与治理

## 1. 现象

进入「我的 → 缓存管理」首屏有可感知的卡顿（掉帧），页面内容短暂空白后一次性刷出。

## 2. 根因

**不是「没写成异步」，而是「异步但没离开主 isolate」。**

Dart 是单线程的：`await` 只让出执行权，**续体仍在原 isolate 上执行**。
缓存页的统计链路全是「每个文件一次 async stat」，于是文件数就是主线程上的
事件循环轮数——首帧被这些续体挤掉。

调用链（修复前）：

| # | 位置 | 问题 |
|---|---|---|
| 1 | `lib/page/cache_manage/logic.dart:21-28` | `build()` 里 `Future.microtask` 立刻跑 `reload()` + `loadDownloads()`，与首帧抢时间 |
| 2 | `lib/page/cache_manage/cache_service.dart` `scanCacheGroups()` | 用 `Future.wait` **同时**发起全部 spec 的统计，所有续体一起涌向主 isolate |
| 3 | `lib/core/utils/unit.dart:8` `directorySize()` | `await for(...) { await entity.length(); }` —— 逐文件异步 stat |
| 4 | `lib/page/cache_manage/cache_service.dart` `_tempResidualSize()` | 额外**递归遍历整个临时目录**，而其中已包含第 2 步刚走过的那些子目录（重复劳动） |

全仓库确认：`lib/page/cache_manage/` 下**没有任何 `compute`/`Isolate`**，
即整条遍历都在主 isolate。

### 实测数据（本机，`flutter test` 内合成目录）

用真实的 `directorySize()` 跑，对比同一批文件的同步写法：

| 文件数 | `directorySize`（逐文件 await） | `listSync` + `lengthSync` |
|---|---|---|
| 500 | 43 ms | 3 ms |
| 2000 | 140 ms | 9 ms |
| 5000 | **200 ms** | **20 ms** |

也就是说：① 这些耗时**全是主线程时间**（200ms ≈ 60fps 下掉 12 帧）；
② 异步写法本身还比同步慢约 **10 倍**。

> 顺带说明：本次新增的「开发者工具箱资源」缓存项会遍历 278 个文件，
> 是这个问题的**贡献者之一**（约 25~40ms），但不是主因。

## 3. 修复

把整批目录统计**移出主 isolate**，并在 isolate 内改用同步 API：

- `cache_service.dart` 新增 `_scanAllSizes()`：把待统计目标整理成
  纯路径数据（`_SizeScanRequest`），一次 `compute()` 交给后台 isolate；
- isolate 侧 `_scanSizesInIsolate()` 用 `listSync` + `lengthSync` 一次跑完；
- 删除主 isolate 上的 `_specSize()` / `_tempResidualSize()`；
- `scanCacheGroups()` 与 `cacheCategorySizes()`（Agent 工具在用）共用同一份统计；
- 排除规则提取为 `_reservedDirs` 常量，避免「统计」与「清理」两处规则漂移。

对外行为不变：分组、展示、单项清理、一键清理、Agent 工具接口全部一致。

## 4. 验证

同一个探针（周期性 timer 模拟帧，记录主 isolate 的最长停顿），3000 个文件：

| | 总耗时 | **主 isolate 最长停顿** |
|---|---|---|
| 修复前（按 2000→140ms / 5000→200ms 折算） | ~150 ms | ~150 ms（全在主线程） |
| **修复后** | **48 ms** | **约 4 ms** |

停顿从「百毫秒级」降到个位数毫秒：目录遍历已完全离开 UI 线程，
且总耗时反而更短（同步遍历 + isolate 启动开销 < 原来的逐文件异步往返）。

## 5. 坑与约定

- **`await` ≠ 不阻塞**。判断一段计算会不会卡 UI，要看「它跑在哪个 isolate」，
  而不是「有没有 await」。O(文件数) 的递归遍历是最典型的反例。
- `lib/core/utils/unit.dart` 的 `directorySize()` 已加警示注释：文件数可能多时，
  必须放进 `compute()` 且改用同步 API。它现在只剩测试在用。
- 后续若再加「按目录统计」的缓存项，**只需往 `_scanAllSizes()` 的 `dirTargets`
  里加一条**，无需关心线程问题。
