# 请求调试

> 使用 Wiki 第九篇 · 抓包联动的 HTTP 调试工具

「请求调试」是一个 Postman 式的原生工具，用来组装、发送、回看 HTTP 请求，并统一管理
抓包产生的改写规则。它与代理内核解耦：既能独立使用，也能接收「抓包」页保存过来的请求。

入口：首页「我的 → 工具 → 请求调试」（路由 `/GStore/requestDebug`）。

## 1. 工作台总览

顶部用分段按钮切换四个分区：

| 分区 | 作用 |
| --- | --- |
| 集合 | 收藏与组织请求（文件夹树 + 请求列表） |
| 历史 | 每次发送的记录，可回看、重发、保存 |
| 环境 | 环境变量表，供 `{{变量名}}` 替换 |
| 改写规则 | 管理代理引擎的实时响应改写规则 |

集合、历史与环境持久化在应用文档目录的 `request_debug_store.json` 中（历史有上限，超出后
自动淘汰最旧的记录，不会无限增长）；改写规则由代理引擎侧持久化并生效（`capture.rules.*`）。

四个分区都支持搜索 / 筛选 / 排序：集合按名称、历史按 URL、环境与规则各自过滤。空结果有
空态提示，清空查询即恢复。

## 2. 集合：组织你的请求

- **文件夹树**：支持嵌套子文件夹，可展开 / 折叠。
- **新建**：用 `+` 新建集合或子文件夹。
- **导入 cURL**：把一段 cURL 命令粘贴进来，自动解析成一条请求；解析时忽略 / 无法处理的
  选项会汇总提示，不会静默丢弃。
- **导入 / 导出集合**：支持 HAR / Postman / OpenAPI / 原始 HTTP（详见 §10）。
- **打开请求**：点击请求进入全屏编辑器。
- **拖拽 / 移动 / 复制**：集合内请求可拖拽排序，也可跨文件夹移动；请求与集合可复制。
- **重命名 / 删除**：在集合或请求上操作；删除请求会危险确认。

## 3. 编辑器：组装请求

进入编辑器后可设置请求名称、方法与 URL，并在以下分段间切换：

| 分段 | 内容 |
| --- | --- |
| 参数 | URL 查询参数（键 / 值） |
| 头 | 请求头（键 / 值） |
| 体 | 请求体；按 `bodyKind` 编码 |
| 认证 | 认证类型与注入位置（Header / Query） |
| Cookie | 请求 Cookie |
| 响应 | 发送后的响应查看器 |

编辑器支持：

- **发送 / 取消**：立即发出请求并切到「响应」分段；发送中可取消，取消不会写入半成品历史。
- **保存 / 另存为**：写入当前集合；另存为会克隆成一条新请求（换新 id，不覆盖同名请求）。
  保存失败会明确报错，不会假装成功。
- **导出 cURL**：把当前请求导出为可复制的 cURL 命令。
- **生成代码**：把当前草稿渲染为多语言片段（详见 §9）。
- **原始请求**：预览当前草稿的方法 / URL / 头 / 体的原始 HTTP 文本。
- **插入环境变量**：从当前环境选择变量，插入 `{{变量名}}`，发送时自动替换。
- **管理 Cookie jar**：按 host 列出 / 清除 / 新增会话 Cookie。

### 3.1 认证与 Cookie 真正生效

- **认证**：Basic → `Authorization: Basic <base64(user:pass)>`；Bearer →
  `Authorization: Bearer <token>`；APIKey → 命名请求头或查询参数（与既有查询合并规则一致，
  同名覆盖而非追加）。认证同时作用于发送与 cURL 导出，`toCurl → parseCurl → 发送` 往返等价。
- **编辑器 Cookie**：发送前并入 `Cookie` 头，与 Cookie jar 同名去重（编辑器显式值优先）。
- **Cookie jar**：采用 RFC 6265 关键修复（Max-Age 优先于 Expires、拒绝公共后缀的两段域
  “超级 Cookie”、跨子域同名去重、重定向后按最终地址归属）。**默认仍是会话内**，应用重启
  后不保留。

### 3.2 请求体编码（`bodyKind`）

`体` 分段选择的类型会**真正决定线缆字节与 Content-Type**，不再一律按 UTF-8 文本发出：

- `json` / `text`：无显式 Content-Type 时给出默认建议；
- `form_urlencoded`：按键值做 URL 编码；
- `multipart`：生成 boundary 与字段 / 文件项；
- `binary`：可选本地文件，或 hex / base64 文本输入。

### 3.3 每请求网络选项

编辑器可对**单条请求**覆盖默认网络行为（默认：30 秒超时 / 跟随重定向 / 使用 Cookie jar /
严格证书）：

- **超时**：毫秒，必须为大于 0 的整数；
- **跟随重定向**：关闭时保留 30x 原样返回；
- **使用 Cookie jar**：关闭时该请求不带 jar 里的 Cookie；
- **跳过 TLS 证书校验**：危险开关，需经统一危险确认弹层二次确认；开启后仅对该请求生效，
  会接受自签名 / 无效证书，只应临时用于你信任的调试目标。

### 3.4 环境作用域与集合级变量 / 鉴权

- 变量继承顺序（后者覆盖前者）：`global → collection（祖先 → 叶子）→ environment → local`。
- 鉴权继承就近优先：`request → 最近的集合（叶子 → 祖先）→ global`。
- 环境变量支持默认值语法；被标记为密钥的变量值改走安全存储（见 §9）。

## 4. 响应查看器

发送后展示状态码、耗时与大小，并提供以下视图：

- **格式化 / 原始**切换，以及**复制**。
- 分段：**头 / Body / Cookie / 原始**。
- Body 按 `Content-Type` 渲染 JSON / XML / HTML / 文本；二进制等非文本用安全占位，
  不渲染原始字节；大 Body 分块加载，避免卡顿。
- **截断标注**：超过上限的响应会标注「已截断」，大小取自 `Content-Length` 的真实值。
- **复制二进制**：以原始字节 / base64 复制，保证字节一致。
- **保存响应体**：把响应体（含二进制）逐字节存盘。
- **保存为改写响应**：把当前响应内容直接带进改写规则编辑器；保存时会剥离
  hop-by-hop / `content-encoding` / `content-length` / `transfer-encoding` 等头，
  错误响应不可保存。

## 5. 历史：回看与重发

- 发送成功后会自动写入历史，并保存一份**响应快照**（超上限按规则截断并标注）。
- 列表展示方法、URL、状态、耗时与时间。
- **重发**：真正再次发送（会先做环境变量替换），并追加一条新历史。
- **保存到集合**：克隆为新请求写入目标集合。
- **响应 diff**：选中两条历史响应，按行比较并高亮新增 / 删除。
- **删除 / 清空**：危险操作二次确认。
- 点击历史行可载入编辑器继续编辑。

## 6. 环境：变量替换

- 维护多个环境，每个环境是一组键 / 值。
- 点左侧图标把某个环境设为**当前环境**；`{{变量名}}` 按当前环境取值。
- 支持新建、编辑、删除环境（删除二次确认）。
- 变量替换同样作用于 URL、头、体与认证字段。
- 支持导出环境 JSON（导出的敏感值以掩码替换，不落明文）。

## 7. 改写规则：联动代理引擎

改写规则是**代理引擎的全局能力**，只对 h1/h2 的 HTTP 请求生效，规则默认**关闭**。
在这里新建 / 编辑 / 开关 / 删除规则：

- **匹配方式**：精确 URL / 通配 / 正则（+ 可选的方法过滤）命中才生效。
- **备注**：每条规则可写一个 `remark` 便于识别。
- **延迟字段（`delayMs`）**：**仅存储、当前不注入延迟**。
- **类型**：
  - `替换响应`：正常请求上游，然后用规则里的状态 / 头 / Body 覆盖响应。
  - `返回本地响应`：不请求上游，直接返回规则里的响应。
- 命中次数会累计展示；删除经二次确认。

> 规则要真正生效，需要代理引擎**开启抓包（MITM）**且目标域名命中白名单；同时规则本身
> 必须处于**启用**状态。证书约束见 §11，完整抓包流程见《网络调试》使用文档。

**WebSocket 不支持改写**：WS 帧只能被抓包捕获查看，规则不会改写 WS 帧。

## 8. 与「抓包」联动

在「网络调试」页开启抓包后：

1. 打开「请求域名 / IP」列表，进入某条请求的**抓包详情**。
2. 详情页提供动作：
   - **保存到请求调试** / **重发到请求调试**：把该请求映射成一条可编辑的请求，写入名为
     「抓包」的集合（集合不存在时自动创建），或直接载入编辑器。
   - **创建改写规则**：跳转到本工作台的「改写规则」分区并预填内容。

## 9. 新能力（本版本交付）

本版本把此前“填了却不生效”的请求调试能力补齐，并新增可离线使用的组织 / 导出能力：

- **真正生效**：认证、编辑器 Cookie、`bodyKind` 请求体编码、每请求网络选项、
  发送中取消、发送写历史并回看响应快照。
- **组织与检索**：集合 / 历史 / 环境 / 规则支持搜索、筛选、排序；集合支持拖拽排序、
  跨文件夹移动、复制、删除确认。
- **导入 / 导出**：HAR / Postman / OpenAPI / 原始 HTTP 集合编解码，环境与规则 JSON
  导出（详见 §10）。
- **响应工具**：历史响应 diff、响应体（含二进制）存盘、原始请求预览。
- **多语言代码生成**：cURL / Dart (Dio) / Python (requests) / JavaScript (fetch) /
  Go (net/http) / HTTPie；`{{变量}}` 占位符在生成片段中逐字保留。
- **作用域变量与集合级鉴权**：`global → collection → environment → local` 继承；
  集合 / 文件夹级变量与鉴权在子请求生效。
- **安全存储与脱敏**：认证密码 / token / APIKey、被标记的环境密钥改走系统安全存储
  （`flutter_secure_storage`），store 只存引用；cURL / 历史 / 环境导出前对密钥脱敏
  （统一替换为 `***`）。
- **存储硬化**：`request_debug_store.json` 带版本迁移（旧明文密钥自动迁移，非法 /
  未来版本降级不抹除），单飞保存防并发损坏，损坏条目被隔离，保存失败对用户可见。

## 10. 导入导出格式

集合级格式（导入时按内容自动识别，也接受文件名后缀）：

| 格式 | 说明 | 默认扩展名 |
| --- | --- | --- |
| HAR 1.2 | HTTP Archive；`log.entries` 结构 | `.har` |
| Postman v2.1 | Postman Collection v2.1 | `.json` |
| OpenAPI 3 | **仅 JSON**（不解析 YAML） | `.json` |
| 原始 HTTP | `.http` / REST Client 风格，`###` 分隔多请求 | `.http` / `.rest` |
| cURL | 单请求导入 / 导出（非集合级） | — |

环境与改写规则单独导出为 JSON（含 `format` / `version` 标识，导入时校验）。

约定与诚实边界：

- **导入会重新铸造 id**，并重映射 `parentId` / 请求的 `collectionId`，不会与现有集合冲突；
  导入目标复用名为「导入」的顶层集合，不存在则新建。
- **失败是结构化的**：空内容 / JSON 截断 / 结构不符 / 无法识别都返回明确错误，绝不抛出
  未捕获异常；单条损坏条目会被隔离，不影响其余条目。
- **环境导出脱敏**：被标记为密钥的变量值以掩码导出，真实值留在设备安全存储中。
- **不引入重型依赖**：OpenAPI 仅支持 JSON；不内置 Java CLI 或 JS 引擎。

## 11. Android CA 约束

「请求调试」本身**不需要**安装任何 CA，也不捕获流量；只有当你使用 **§7 改写规则**并让
代理引擎开启抓包（MITM）时，才涉及 CA。要点：

- **抓包解密依赖设备信任抓包根证书**：需先生成 CA，再导出并安装到设备证书存储。
- **无 root 只能安装用户证书**：Android 7+ 默认不信任用户证书的应用无法被解密。
- **证书固定（pinning）的 App 不信任本 CA**，其 HTTPS 无法被抓取；工具不绕过 pinning。
- **跳过上游证书校验**（抓包设置里的危险开关）只解决“上游本就是自签名 / 企业中间代理”
  的场景，开启后只保证机密性、不保证认证性，绝不应在普通公网开启。
- 安装 / 信任状态是 **best-effort 探测**：仅展示「已安装 / 尚未安装 / 无法确认 / 平台不
  支持」，不会把“无法检测”谎报成“未安装”。
- 真机安装路径的验证状态见《代理内核与 VPN》§10；本仓库无 adb 设备时相关路径标注
  UNVERIFIED。

完整 CA 生命周期与抓包流程见《网络调试》使用文档与《代理内核与 VPN》§5.1。

## 12. 非 root · pinning · UDP/QUIC 限制

以下限制**必须如实告知用户**，UI 也会诚实提示：

- **非 root 抓不到任意 App**：HTTPS 解密依赖设备信任抓包根证书；无 root 只能安装**用户
  证书**，Android 7+ 默认不信任用户证书的应用（大量第三方 App）无法被解密。**不绕过证书
  固定（pinning）**。
- **UDP / QUIC 不抓**：只捕获 TCP；HTTP/3（QUIC/UDP）流量既不终止也不记录。
- **WS 只抓帧、不支持改写**：WebSocket 帧可捕获展示，规则不会改写 WS 帧。
- **发送走应用默认网络**：请求调试发出的请求跟随应用默认网络路径，不保证经代理隧道。
- **Cookie jar 默认会话内**：应用重启后不保留。
- **断点（拦截）能力尚未实现**：契约草图（`captures.breakpoint.*` /
  `proxy.capture.breakpoint` 事件）已冻结且默认关闭，但 MITM 暂停 / 恢复数据面未实现，
  当前调用返回 `PROXY_CAPTURE_BREAKPOINT_NOT_IMPLEMENTED`。详见
  `.omo/plans/proxy-breakpoint-dataplane.md`。

安装与信任抓包证书的步骤见「网络调试 → 抓包设置 → 证书管理」。
