5) Caveat — this is NOT a wall-clock gate
------------------------------------------------------------------
The benchmark is release-mode with a warm page cache: it measures query-engine cost only, and `new` (16ms) is in
fact SLOWER than `legacy` (8ms) in that regime because the two-step path issues two statements. The real cold-start
win comes from step (a) being a COVERING INDEX scan that never reads the `metadata`/`versions` JSON blobs, so the
44s cold I/O amplification disappears; that is an I/O effect warm-cache timing cannot reproduce. Therefore the
benchmark is NOT a wall-clock gate for the cold-start scenario — the gate is the query-plan shape asserted above.
