## Final-wave fixes in detail

These are the fixes that closed the F1/F3 rejections and the two extra findings from the first final-wave review.

| Fix | Behavior now | Quoted proof | Source |
|---|---|---|---|
| A | With `CoreFlags.install == true`, an app install that resolves to no core `download_task` logs `CORE_E_INSTALL_NO_CORE_TASK` and returns `(false, InstallMethod.system)`; it never calls Shizuku/AppInstaller. Only an explicitly module-owned APK (`installApk(..., moduleInstall: true)`) keeps the legacy path. | `flag-on missing core task result=(false, InstallMethod.system) commands=0` and `module APK result=(true, InstallMethod.shizuku) commands=1` | `88-final-wave-fix.txt` FIX A |
| B | The legacy import resolves before the first core read in `_findCoreTaskId` and `installTask`. | `install import order: [import, list]` | `88-final-wave-fix.txt` FIX B |
| C | `DownloadApi.list` and every `watchAll` tick take the same `refresh_and_list()` path: best-effort reconcile, then core read. A reconcile failure is logged; only a core read failure stops the watch. | `download_api refresh first: [ ... status: "running", bytes_done: 0 ... ]`, `download_api refresh second: [ ... status: "completed", bytes_done: 100 ... ]` | `88-final-wave-fix.txt` FIX C |
| D | Async install results are pumped to the durable row. Rust runs a 500 ms `gstore-install-reconcile` thread; Dart runs a bounded pending poller (500 ms tick, max 180 s, one per module task id) that stops on `installed/failed/denied/timeout/unknown` and is cancelled by `resetForTest`. | `install pump calls: [reconcile, install:7, reconcile, get:7, reconcile, get:7]`; `terminal install calls: [reconcile, install:7]` | `88-final-wave-fix.txt` FIX D |
